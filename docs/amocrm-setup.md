# Настройка интеграции с amoCRM (OAuth 2.0)

## Пошаговая инструкция

### Шаг 1. Создайте интеграцию в amoCRM

1. Войдите в ваш аккаунт amoCRM.
2. Перейдите в **Настройки** → **Интеграции**.
3. Нажмите **+ Создать интеграцию** (тип: **Внешняя интеграция**).
4. Заполните:
   - **Название** — произвольное, например «Сайт Спецтехмаш».
   - **Redirect URI** — укажите URL вашего сервера, например `https://yourdomain.ru/api/amocrm/auth` (или `http://localhost:3001/api/amocrm/auth` для разработки).
5. После создания интеграции скопируйте:
   - **ID интеграции** (это `AMOCRM_CLIENT_ID`)
   - **Секретный ключ** (это `AMOCRM_CLIENT_SECRET`)

### Шаг 2. Настройте переменные окружения

Откройте файл `.env` (или создайте его из `.env.example`) и заполните:

```env
AMOCRM_DOMAIN=ваш-поддомен.amocrm.ru
AMOCRM_CLIENT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
AMOCRM_CLIENT_SECRET=длинная_строка_секрета
AMOCRM_REDIRECT_URI=https://yourdomain.ru/api/amocrm/auth
AMOCRM_PIPELINE_ID=12345  # необязательно
```

> **Важно:** `AMOCRM_REDIRECT_URI` в `.env` должен **в точности** совпадать с тем, что указан в настройках интеграции в amoCRM.

### Шаг 3. Получите код авторизации

1. В настройках вашей интеграции в amoCRM нажмите кнопку **«Авторизовать»** (или используйте ссылку авторизации).
2. amoCRM покажет вам **код авторизации** — это длинная строка, которая действует **20 минут**.
3. Скопируйте этот код.

### Шаг 4. Обменяйте код на токены

Запустите сервер:

```bash
npx tsx server/index.ts
```

Затем выполните GET-запрос к эндпоинту `/api/amocrm/auth` с вашим кодом:

```bash
curl "http://localhost:3001/api/amocrm/auth?code=ВАШ_КОД_АВТОРИЗАЦИИ"
```

Если всё настроено правильно, вы получите ответ:

```json
{ "success": true, "message": "Токены amoCRM успешно получены и сохранены." }
```

В корне проекта появится файл `amocrm_tokens.json` с токенами. **Не коммитьте этот файл!** Он уже добавлен в `.gitignore`.

### Шаг 5. Готово!

Теперь система автоматически:
- Использует `access_token` из `amocrm_tokens.json` для API-запросов.
- Обновляет токены до истечения срока действия (access token живёт ~24 часа).
- При получении ответа `401 Unauthorized` — автоматически обновляет токен и повторяет запрос.

## Как это работает

```
┌─────────────────────────────────────────────────┐
│  1. Пользователь отправляет заявку на сайте     │
│  2. Сервер вызывает pushToAmoCRM()              │
│  3. getValidAmoToken() читает amocrm_tokens.json│
│  4. Если токен истёк → refreshAccessToken()     │
│  5. Новые токены сохраняются в файл             │
│  6. Запрос к API amoCRM с актуальным токеном    │
│  7. Если 401 → обновить токен, повторить запрос │
└─────────────────────────────────────────────────┘
```

## Частые вопросы

**Q: Что делать, если `amocrm_tokens.json` удалён или повреждён?**
A: Повторите шаги 3–4 (получите новый код авторизации и обменяйте его).

**Q: Можно ли использовать старый `AMOCRM_ACCESS_TOKEN` из `.env`?**
A: Нет. Система полностью перешла на OAuth 2.0 с автоматическим обновлением токенов. Переменная `AMOCRM_ACCESS_TOKEN` больше не используется.

**Q: Как часто обновляется токен?**
A: Срок жизни access token определяется amoCRM (обычно ~24 часа, но может отличаться). Система обновляет его автоматически за 5 минут до истечения на основе значения `expires_in` из ответа API.
